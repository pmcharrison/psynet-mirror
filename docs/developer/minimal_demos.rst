Demo directories and scaffolding
================================

PsyNet demo directories include just the essential experiment files together with
any demo-specific support code, templates, or assets. In practice this means you
should expect to see files such as ``experiment.py``, ``requirements.txt``, and
``constraints.txt`` in the repository, plus any demo-specific helpers.

To run a demo yourself, you must generate several additional boilerplate files.
You can do this by running ``psynet scaffold`` in your terminal.

Demo file policy
----------------

Keep in each demo directory:

- ``experiment.py``
- ``requirements.txt``
- ``constraints.txt``
- demo-specific helper modules
- demo-specific templates, static files, and assets
- a short, demo-specific ``README.md``

Generate on demand with ``psynet scaffold``:

- ``.gitignore``
- ``.dockerignore``
- ``Dockerfile``
- ``config.txt``
- ``test.py``
- ``pytest.ini``
- ``AGENTS.md``
- ``.python-version``
- ``Dockertag``
- ``.github/workflows/test.yml``
- ``.vscode/launch.json``
- ``docker/``

Why ``constraints.txt`` stays
-----------------------------

Even though ``constraints.txt`` is autogenerated, we keep it in the demo
directories because it remains the documented installation and reproducibility
path for running demos locally.

Audit workflow
--------------

Use the audit script to inspect the current demo tree without modifying it:

.. code-block:: bash

   python demos/audit_minimal_demos.py

Useful variants:

.. code-block:: bash

   python demos/audit_minimal_demos.py --only-nonminimal
   python demos/audit_minimal_demos.py --demo demos/features/api
   python demos/audit_minimal_demos.py --json

The script reports, for each demo:

- whether it already contains only the essential files
- which scaffold-managed paths would be removed
- which preserved paths would remain
- whether the README still matches the generic template
- whether scaffold-managed files or directories appear to be customized

Validation workflow
-------------------

Representative round-trip validation lives in the test suite. It works by copying
selected demos to temporary directories, pruning scaffold-managed files from the
copy, regenerating them with ``psynet scaffold``, and checking that authored files
are unchanged. Selected demos are also exercised with ``psynet test local`` after
the round trip, and relative-import demos are included to ensure that removing
``__init__.py`` from the repository copy does not change import behavior.

Run the targeted validation with:

.. code-block:: bash

   python -m pytest tests/isolated/test_minimal_demo_roundtrip.py -q
