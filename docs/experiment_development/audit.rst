Experiment audits
=================

An **experiment audit** is a portable ``audit/`` folder that packages evidence
that an experiment was implemented and validated. It records artifacts, checks,
and blockers for human inspection, then renders a static HTML site.

The audit CLI does **not** run tests or collect evidence for you. Agents or
experimenters gather artifacts with the usual PsyNet commands
(``psynet test local``, ``psynet simulate``, performance tests, exports, and so
on), then record the outcomes in ``audit/audit.json``.

Install the optional extra when you need the renderer:

.. code-block:: bash

   uv pip install -e '.[audit]'

Commands
--------

.. code-block:: bash

   psynet audit init
   psynet audit validate
   psynet audit render

* ``init`` creates a starter ``audit/`` directory whose required-but-missing
  artifacts are covered by starter blockers.
* ``validate`` checks the manifest structure, required artifact files, blocker
  coverage, video limits, and notebook JSON readiness.
* ``render`` builds a self-contained static site under ``audit/site/``.

There is also a console script alias ``psynet-audit`` with the same
``init`` / ``validate`` / ``render`` subcommands.

Bundle layout
-------------

.. code-block:: text

   audit/
     audit.json
     PROMPT.md
     PLAN.md
     TIMELINE.md
     REPORT.md
     artifacts/
     analyses/
     logs/
     site/          # generated by render; usually not committed

``audit.json`` is the machine-readable manifest. Markdown section files provide
review context. Incomplete required artifacts must be represented by blockers
rather than hidden by rendering.

Python API
----------

Shared helpers live under :mod:`psynet.audit` (model classification, HTML
rendering, and artifact sanitization). These modules intentionally avoid
importing the experiment runtime or Dallinger so they can be reused by light
tooling such as the PsyNetSkills dashboard exporter.
