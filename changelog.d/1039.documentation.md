Documented the changelog fragment workflow:
- Contributors commit only fragment files, never a regenerated `CHANGELOG.md`; the rendered `## Unreleased` block is refreshed by the maintainer at release time via `--release`.
- Date-based fallback (`YYYYMMDD.<category>.md`) for direct pushes to `master`, which the CI `changelog_check` job cannot enforce since it only runs on MRs.
- Explicit fragment naming, supported categories, and ordering conventions in `AGENTS.md` and `changelog.d/README.md`. (author: [Frank Höger])
