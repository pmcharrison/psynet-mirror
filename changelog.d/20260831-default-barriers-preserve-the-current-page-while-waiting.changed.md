``wait_while``, ``AsyncCodeBlock(wait=True)``, trial feedback processing, and default barriers now preserve the current page, use shared wake notifications when available, and credit actual visible waiting time; progress and advertised duration continue to use ``expected_wait``, and an explicit ``WaitPage`` or custom waiting logic retains a dedicated waiting screen. ``AsyncCodeBlock`` now uses a 2-second fallback check interval, and while-loop timeouts use precise elapsed seconds and trigger when the configured limit is reached.
